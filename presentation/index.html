Objectif

Pourquoi ce
projet ?

Concevoir une API REST complète et sécurisée, couvrant l'ensemble des besoins d'un backend moderne : authentification robuste, gestion des accès, persistance des données et documentation interactive.

01
🔐

Authentification JWT

Système d'authentification stateless basé sur des tokens JWT. Inscription, connexion et validation sécurisée à chaque requête.

02
👤

Gestion des Rôles

Contrôle d'accès basé sur les rôles (RBAC). Différenciation des permissions entre utilisateurs standard et administrateurs.

03
📦

CRUD Produits

Endpoints complets pour la création, lecture, mise à jour et suppression des produits, avec persistance MongoDB.

04
📖

Documentation Swagger

Interface Swagger UI auto-générée permettant d'explorer et de tester tous les endpoints directement depuis le navigateur.

Architecture MVC Spring

Séparation stricte des responsabilités en couches distinctes. Chaque composant a un rôle unique, facilitant la maintenabilité et les tests.

Stateless Aucune session côté serveur. Le JWT porte toute l'information d'identité.
Filter Chain JwtAuthFilter intercepte avant le contrôleur. Zéro accès non autorisé possible.
Repository Pattern MongoRepository abstrait toute la persistance. findBy*, save(), deleteById() out-of-the-box.

Anatomie du token JWT RFC 7519
HEADER
{
  "alg": "HS256",
  "typ": "JWT"
}
.
PAYLOAD
{
  "sub": "user@email.com",
  "role": "USER",
  "iat": 1715000000,
  "exp": 1715086400
}
.
SIGNATURE
HMACSHA256(
  base64(header) + "."
  + base64(payload),
  SECRET_KEY
)
⏰ 24h par défaut 🔄 Refresh possible 🚫 Stateless 🔐 HS256

Démonstration

API
Endpoints

http://localhost:8080/swagger-ui/index.html
LETS-PLAY API — OpenAPI 3.0
auth-controller
POST /auth/register Inscription
POST /auth/login Connexion → JWT
user-controller
GET /users Liste 🔒
GET /users/{id} Détail 🔒
DEL /users/{id} Supprimer 🔒
product-controller
GET /products Catalogue
POST /products Créer 🔒
PUT /products/{id} Modifier 🔒
DEL /products/{id} Supprimer 🔒
01
S'inscrire / Se connecter POST /auth/register puis POST /auth/login. La réponse contient le token JWT à copier.
02
Cliquer sur Authorize 🔓 Dans Swagger UI, coller le token dans le champ "Bearer {token}" et valider.
03
Try it out → Execute Sélectionner n'importe quel endpoint protégé 🔒, remplir le body et cliquer Execute.
04
Voir la réponse JSON Code 200/201 → données. Code 401/403 → accès refusé sans token valide.
Flux CRUD complet
Phase 1 Authentification POST /auth/login → 200 OK
Phase 2 Création produit POST /products → 201 Created
Phase 3 Persistance MongoDB db.products.insertOne({"{...}"})
Phase 4 Récupération GET /products → 200 OK [{"{...}"}]
